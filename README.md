# humanizer-zh

中文表达编辑 skill，处理翻译腔、模板腔和聊天残留，保留原意、作者立场和文体。普通润色默认返回最终文本；审阅默认只诊断，明确要求修改文件时才写回。

## 本次对齐

2026-10-03 检查 [blader/humanizer](https://github.com/blader/humanizer) 时，上游主分支的 SKILL.md 标记为 **3.1.0**。[更新记录](https://github.com/blader/humanizer/blob/main/CHANGELOG.md)说明，3.0 将 35 个模式合并为 25 个，强化结构优先的检查；3.1 增加对话回复的读者上下文判断，形成 26 个模式。本版吸收这两次更新中适合中文的做法，不代表与上游逐条一致。

| 变更方向 | 中文版处理 |
|---|---|
| 先检查结构问题 | 加入虚设对立、重复收尾、预告开场、机械节奏、空泛关系与正文制作说明 |
| 全段改写与改后检查 | 先核对语义，再查残留的结构问题，不强制产生第二份不同稿件 |
| 防止合并时丢信息 | 明列比较、排名、先后、同时性和缩写定义 |
| 匹配作者样本 | 样本风格优先，保留个人习惯，不新增经历或反应 |
| 对话中的已知背景 | 结论前置，合并重复；未经摘要授权保留独有论据 |
| 文件和嵌入任务 | 保护命令、路径、数据等；按用户授权决定是否写入 |

保留中文版已有的选择：不按词表判定作者身份，不全面禁用中文破折号或弯引号，不擅自补写情绪，不因归因含糊就删除原文主张，不把广告和个人写作统一改成中性说明文，也不默认向用户展示初稿和复查过程。

## 文件结构

- `SKILL.md`：常用编辑规则、结构检查和交付方式。
- `references/conditional-modes.md`：摘要、创作、核查、文体、对话回复与语义边界示例，按任务读取。
- `UPSTREAM-LICENSE.txt`：上游版权与 MIT 许可。

运行时仍是入口加一个条件参考文件。此次新增了检查能力，文本体积有所增加；[旧版 README](https://github.com/AlexBybye/humanizer-CN/blob/ccfbeef/README.md) 中关于压缩比例、测试数量和运行时摘要的结论只对应旧版，不能作为新版的验证结果。

## 使用示例

- “润色这段中文，保留所有数字、归因和限制，只给终稿。”
- “参考这两段文字调整语气，不新增观点。”
- “只审阅这份文件的翻译腔，不要修改。”
- “修改这份 Markdown 的正文，保留代码和链接。”
- “结合前面的讨论润色这条回复，把决定放前面。”
